# Architecture Decision Records

Last updated: 2026-05-22

ADRs capture durable decisions that shape future implementation. They should be
short, dated, and linked from related docs.

## Index

| ADR | Status | Decision |
| --- | --- | --- |
| [0001](0001-versioned-feature-docs-and-tracking-hubs.md) | Accepted | Use versioned feature docs plus lightweight project tracking hubs. |

## Template

```markdown
# ADR NNNN: Title

Date: YYYY-MM-DD
Status: Proposed / Accepted / Superseded

## Context

What problem or tradeoff forced the decision?

## Decision

What are we choosing?

## Consequences

What becomes easier, harder, or explicitly out of scope?

## Links

- Related docs, issues, or code.
```
