# Scenario Recommendation V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert saved scenarios into structured, cautious recommendations with deterministic runtime decisions and evaluation-ready metadata.

**Architecture:** V1 extends the existing scenario contract instead of adding a parallel product surface. AI-service can emit recommendation intent, the API normalizes it into `ScenarioResponse`, the runtime evaluator computes current action with strict gates, and the web UI surfaces the recommendation through Thesis Detail and Scenario Monitor.

**Tech Stack:** Python AI-service with Pydantic models, NestJS/TypeScript API, existing journal repository, React/Vite frontend, Node test runner, pytest.

## One Outcome

Scenario Recommendation V1 makes each scenario inspectable as an operational
recommendation, not just a descriptive branch.

V1 should let the system answer:

```text
For this short/mid/long scenario, should I wait, consider action, enter now,
avoid, reduce, exit, or review?
Why?
What must happen first?
What blocks action?
What invalidates this recommendation?
How will we later know whether this recommendation worked?
```

## Resolved Decisions

- V1 uses the name `Scenario Recommendation`.
- V1 does not continue Research Continuity as the main product direction.
- V1 keeps horizon identity as an existing scenario dimension.
- V1 keeps `decision_playbook` compatibility but adds
  `scenario_recommendation` as the clearer product contract.
- V1 uses deterministic runtime evaluation for current action.
- V1 downgrades uncertain cases instead of filling gaps optimistically.
- V1 prepares evaluation metadata but does not persist final scenario outcomes.
- V1 uses existing scenario surfaces instead of creating a new scenario route.

## Contract

Add these API-facing types beside the existing decision types:

```ts
export type ScenarioRecommendationAction =
  | 'wait'
  | 'consider_long'
  | 'consider_short'
  | 'entry_long_now'
  | 'entry_short_now'
  | 'avoid'
  | 'reduce'
  | 'exit'
  | 'review';

export type ScenarioRecommendationBias = 'long' | 'short' | 'neutral' | 'unknown';

export type ScenarioEvaluationReadiness =
  | 'ready'
  | 'missing_trigger'
  | 'missing_invalidation'
  | 'missing_time_window'
  | 'not_actionable'
  | 'needs_review';

export interface ScenarioRecommendationGate {
  id: string;
  label: string;
  status: 'passed' | 'failed' | 'pending' | 'unknown';
  reason: string;
}

export interface ScenarioRecommendation {
  version: 'scenario_recommendation.v1';
  generated_at: string | null;
  source: 'llm' | 'derived_v1';
  action: ScenarioRecommendationAction;
  action_bias: ScenarioRecommendationBias;
  confidence: number;
  summary: string;
  thesis_link: string;
  required_conditions: ScenarioDecisionCondition[];
  invalidation_conditions: ScenarioDecisionCondition[];
  wait_for: string[];
  hard_gates: ScenarioRecommendationGate[];
  blocking_reasons: string[];
  risk_notes: string[];
  evidence_refs: ScenarioEvidenceRef[];
  valid_until: string | null;
  evaluation_readiness: ScenarioEvaluationReadiness;
  evaluation_window: {
    starts_at: string | null;
    ends_at: string | null;
    horizon: 'short_term' | 'mid_term' | 'long_term' | 'unknown';
    metric_hint: 'trigger_then_mfe_mae' | 'avoidance_check' | 'manual_review';
  };
}

export interface ScenarioEvaluationSnapshot {
  version: 'scenario_evaluation_snapshot.v1';
  readiness: ScenarioEvaluationReadiness;
  planned_evaluation_at: string | null;
  expected_horizon: 'short_term' | 'mid_term' | 'long_term' | 'unknown';
  trigger_observed: boolean | null;
  invalidation_observed: boolean | null;
  max_favorable_excursion: number | null;
  max_adverse_excursion: number | null;
  outcome: 'pending' | 'not_ready' | 'inconclusive';
  notes: string[];
}
```

Add these fields to `ScenarioResponse`:

```ts
scenario_recommendation: ScenarioRecommendation | null;
evaluation_snapshot: ScenarioEvaluationSnapshot | null;
```

`runtime_decision` remains a computed current-state field. When both
`scenario_recommendation` and `runtime_decision` exist, the UI should show the
runtime action first and use the recommendation for explanation, gates, and
evaluation context.

## Runtime Gate Policy

`entry_long_now` and `entry_short_now` are allowed only when all of these are
true:

```text
trigger_status = triggered
validity_status = valid
market data is fresh
price is not missing
recommendation confidence >= 0.70
invalidation condition exists
required entry conditions are matched
no failed hard gates
no blocking reasons
scenario is not expired
scenario is not overextended
action_bias matches direction
```

Near-trigger cases may emit `consider_long` or `consider_short`, never
`entry_*_now`.

Unknown, neutral, missing, stale, expired, invalidated, conflicted, or
overextended cases must emit `wait`, `avoid`, or `review` with blocking reasons.
