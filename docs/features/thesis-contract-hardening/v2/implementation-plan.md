# Thesis Contract Hardening V2 Implementation Plan

Last updated: 2026-06-11
Status: draft goal-ready implementation plan

## Goal-Ready Prompt

```text
/goal Implement Thesis Contract Hardening V2 end-to-end.

Read these documents first:
docs/features/thesis-contract-hardening/README.md
docs/features/thesis-contract-hardening/v1/implementation-plan.md
docs/features/thesis-contract-hardening/v2/implementation-plan.md

Objective:
- Replace raw LLM full-thesis prose with deterministic compiled thesis text
  rendered from validated structured fields.

Required behavior:
- Keep the V1 validation gate intact.
- Add a deterministic `ThesisCompiler`.
- `TradeThesis.thesis_text` for new-contract theses is generated by the
  compiler, not copied from raw Portfolio Manager prose.
- Preserve raw Portfolio Manager text only as audit/debug metadata, not as the
  user-facing source of truth.
- Compiler output must include the key sections users already expect:
  main stance, reasons, risk, confirmation, invalidation, missing data, and
  monitor-next guidance.
- API and UI can distinguish compiled, legacy, degraded, and blocked thesis
  text.
- UI renders compiled full thesis and surfaces validation/audit status without
  requiring users to inspect raw JSON.
- Focused tests prove compiler determinism, field coverage, legacy fallback,
  blocked/degraded display, and API compatibility.

Do not implement:
- A new LLM call to rewrite the final thesis.
- A broad thesis detail redesign beyond status and compiled-render support.
- Historical backfill or migration of old thesis text.
- Calibration changes.
- Scenario/alert monitoring strategy changes beyond respecting blocked thesis
  status.
- Evidence drilldown pages. A later version can add line-to-evidence drilldown.

Definition of done:
- New valid/degraded thesis records have compiled `thesis_text`.
- Raw model prose is no longer the primary user-facing full thesis for new
  records.
- Compiler output is deterministic for the same validated candidate.
- Blocked artifacts do not show a normal full thesis.
- API and UI preserve legacy thesis readability.
- Focused AI-service, API, and web tests pass, or exact blockers are documented.
```

## One Outcome

Make `FULL THESIS` an artifact rendered by code.

After V2, the model proposes structured content, V1 validates it, and V2
compiles it into the full thesis text. The saved `thesis_text` becomes a
deterministic representation of validated fields rather than an LLM-authored
blob that downstream systems must trust.

## Dependency On V1

V2 should start only after V1 exists or equivalent behavior is already present:

- structured thesis candidate boundary;
- validation status;
- validation issues;
- degraded/blocked behavior;
- additive API fields for thesis status;
- tests around structured-output failure and missing critical fields.

If V1 is incomplete, implement V1 first.

## Verifiable End State

- [ ] `ThesisCompiler` exists as a small isolated module.
- [ ] Compiler input is validated candidate/summary data, not raw prose.
- [ ] Compiler output is deterministic for identical input.
- [ ] `TradeThesis.thesis_text` for new valid/degraded artifacts comes from the
      compiler.
- [ ] Raw Portfolio Manager markdown is stored only as audit/debug metadata if
      it is retained at all.
- [ ] Compiled text includes status-aware caveats for degraded artifacts.
- [ ] Blocked artifacts do not produce a normal full thesis.
- [ ] Legacy rows still display their original `thesis_text`.
- [ ] API exposes whether thesis text is `compiled`, `legacy`, `diagnostic`, or
      `missing`.
- [ ] Thesis detail UI labels compiled/degraded/blocked/legacy states clearly.
- [ ] Tests cover compiler sections, deterministic output, field omission rules,
      and backward compatibility.

## Compiler Contract

V2 should introduce a deterministic compiler with a contract like:

```python
class ThesisTextSource(str, Enum):
    COMPILED = "compiled"
    LEGACY = "legacy"
    DIAGNOSTIC = "diagnostic"
    MISSING = "missing"


class CompiledThesis(BaseModel):
    text: str
    source: ThesisTextSource
    sections: list[CompiledThesisSection]
    omitted_sections: list[str]
    caveats: list[str]


class CompiledThesisSection(BaseModel):
    key: str
    title: str
    text: str
    source_fields: list[str]
```

Names can change to match repo style. The behavior should not change:

- compiler input is validated structured data;
- compiler output is deterministic;
- section metadata tracks which fields produced which text;
- legacy and blocked behavior is explicit.

## Compiled Text Shape

The V2 compiler should produce a readable plain text or markdown block with
stable sections:

```text
Stance: <rating/direction/confidence summary>

Thesis: <action summary plus investment thesis>

Key reasons:
- <reason 1>
- <reason 2>

Risks:
- <risk 1>
- <risk 2>

Confirmation:
<confirmation condition>

Invalidation:
<invalidation condition>

Monitor next:
- <watchpoint 1>
- <watchpoint 2>

Data caveats:
- <missing or degraded data note>
```

The exact titles can follow existing UI copy, but section order should be
stable because tests and users will rely on it.

## Rendering Rules

### Valid Thesis

For `artifact_status = valid`:

- render all available required sections;
- do not include validation warnings unless they are informational;
- use final capped confidence, not raw model confidence;
- use structured reasons, risks, and monitor-next items;
- never parse raw prose to fill missing critical sections.

### Degraded Thesis

For `artifact_status = degraded`:

- render the thesis, but include a visible caveat section;
- include degradation reasons in `Data caveats` or a similar stable section;
- use confidence after caps;
- avoid language that makes degraded output look equally trustworthy.

### Blocked Artifact

For `artifact_status = blocked`:

- do not render normal full thesis sections;
- render diagnostic text only, for example:

```text
Thesis blocked.
Reasons:
- missing_confirmation_condition
- structured_candidate_missing
```

- set text source to `diagnostic` or `missing`, not `compiled`.

### Legacy Artifact

For legacy rows:

- preserve existing `thesis_text` as readable text;
- set text source to `legacy`;
- do not pretend legacy text has compiled section provenance;
- UI should show a light legacy contract caveat when useful.

## Integration Points

### Thesis Builder

`ThesisBuilder` should call the compiler after V1 validation:

```text
final_state
  -> candidate
  -> validation_result
  -> compile(candidate, validation_result)
  -> TradeThesis(thesis_text=compiled.text, text_source=compiled.source)
```

The builder should retain raw model output only under an audit/debug field if
the repo already has a suitable metadata location.

### Domain And Persistence

Additive `TradeThesis` fields:

```text
thesis_text_source
compiled_sections
compiler_version
raw_model_thesis_text
```

`raw_model_thesis_text` should be optional and should not be returned as the
primary thesis body in public API responses.

### API Contract

`ThesisResponse` should expose:

```ts
thesis_text: string;
thesis_text_source: 'compiled' | 'legacy' | 'diagnostic' | 'missing';
compiled_sections: CompiledThesisSectionResponse[];
compiler_version: string | null;
artifact_status: 'valid' | 'degraded' | 'blocked' | 'legacy';
validation_issues: ThesisValidationIssueResponse[];
```

API rules:

- `thesis_text` remains present for compatibility;
- new clients can inspect `thesis_text_source`;
- blocked artifacts should not expose raw model prose as `thesis_text`;
- legacy rows continue to return their stored text.

### UI Contract

Thesis detail should:

- show compiled full thesis for valid/degraded records;
- show status and caveats above or near full thesis;
- show blocked diagnostic state instead of a normal full thesis;
- show legacy caveat only when a row lacks compiler metadata;
- avoid building thesis sections by parsing raw text in React.

This is not a broad redesign. It is a trust/status rendering update.

## Audit Trail

V2 should preserve enough data to debug a thesis without trusting hidden model
behavior:

```text
candidate_schema_version
validation_result
compiler_version
prompt_version
model_provider
model_name
raw_model_thesis_text optional
compiled_sections.source_fields
```

Audit metadata should be bounded. Do not store huge prompts or secret-bearing
provider payloads in public thesis responses.

## Constraints And Non-Goals

Explicitly do not:

- call another LLM to polish or rewrite the compiled thesis;
- add a new public endpoint just to fetch compiler sections;
- backfill historical thesis rows;
- redesign Calibration Lab;
- build evidence drilldown navigation;
- remove existing `thesis_text` from API responses;
- delete raw legacy text.

- Inspect API response and confirm raw model text is not the primary thesis
  body for new-contract records.

## Checkpoint Behavior

Work milestone by milestone:

1. Add compiler contract and unit tests.
2. Implement deterministic compiled text sections.
3. Wire compiler into `ThesisBuilder` after validation.
4. Add domain/API fields for text source and compiled sections.
5. Update thesis detail UI for compiled/degraded/blocked/legacy display.
6. Add API and web tests.
7. Run focused and broader validation commands.

After each checkpoint:

- run the smallest relevant validation;
- keep Phase 2 scoped to rendering and audit;
- stop if missing V1 behavior blocks safe compiler integration.

## Stop Rules

Stop and report instead of expanding scope when:

- V1 validation status is not available;
- compiler integration would require removing public `thesis_text`;
- legacy compatibility would require broad migration/backfill work;
- UI changes expand into a thesis detail redesign;
- tests reveal unrelated API or web failures outside thesis compiler scope.
