# Workspace-Scoped Research Flows Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to execute this plan.

**Goal:** Add workspace-scoped research flows where each fixed-symbol workspace owns one canonical symbol such as `BTC/USDT`, research runs use that workspace symbol, and legacy mixed workspaces remain readable but cannot create new research runs.

**Architecture:** Store workspace scope metadata on the API side and treat it as authoritative. The frontend reads the active workspace metadata, shows the symbol as workspace context instead of a free input, and still sends `symbol` temporarily for API compatibility. The API validates or derives the run symbol from the workspace before creating a research run.

**Tech Stack:** NestJS API, React + TypeScript web app, Zustand workspace store, existing generated API client, existing Vitest test setup.

---

## Decisions

1. Workspace is a research flow, not just a UI preference.
2. Fixed-symbol workspaces use `scope_type: "fixed_symbol"` and require a canonical `symbol`.
3. Existing `local` workspace becomes `scope_type: "legacy_mixed"` with `symbol: null`.
4. Legacy mixed workspaces are read-only for new research runs in V1.
5. Users can create multiple fixed-symbol workspaces for the same symbol later, differentiated by workspace name or future strategy/timeframe metadata.
6. Workspace IDs are generated by the backend. Users only choose display name and symbol.
7. Canonical crypto symbol format is `BASE/USDT`; the backend normalizes flexible inputs like `btc`, `BTCUSDT`, and `BTC/USDT`.
8. `market_type` belongs to workspace metadata as `mixed | spot | perp`, but V1 does not enforce spot/perp at workspace level. Research run `market_type` remains the current `spot | perp` contract.
9. `default_timeframe` can be stored on workspace metadata but is not enforced in V1.
10. For fixed-symbol workspaces, `workspace.symbol` overrides `?symbol=` and old free-symbol UI.
11. List pages hide symbol filters for fixed-symbol workspaces and keep them for legacy mixed workspaces.

## Success Criteria

1. API exposes list, create, and get workspace metadata.
2. API rejects research run creation in `legacy_mixed` workspace with a stable error code.
3. API rejects mismatched request symbol in fixed-symbol workspace with `400 symbol_workspace_mismatch`.
4. API can create a run without a client-supplied symbol when the active workspace is fixed-symbol.
5. Web workspace switcher shows workspace name, scope, and fixed symbol.
6. Top command strip and research form are workspace-first: fixed workspace shows read-only symbol; legacy mixed disables run creation.
7. Continuity, history, and thesis filters use workspace symbol automatically in fixed-symbol workspaces and do not show redundant symbol filters.
8. Existing tests pass, with focused tests added for workspace metadata, run validation, and fixed-symbol UI behavior.

### 3. Enforce workspace symbol during research run creation

Files:
- `apps/api/src/research-runs/dto/create-research-run.dto.ts`
- `apps/api/src/research-runs/research-runs.service.ts`
- `apps/api/test/api-contract.test.ts`

DTO changes:
- Make `symbol` optional for create requests:
  - fixed-symbol workspace can derive it
  - old clients can keep sending it
- Keep `market_type` as current `spot | perp`; do not expand run market type to `mixed`.

Service behavior:
1. Resolve `workspace_id` from body/header as today.
2. Load authoritative workspace metadata.
3. Enforce editor access.
4. If workspace is `legacy_mixed`, throw `BadRequestException` with:
```ts
{
  code: "legacy_workspace_read_only",
  message: "Legacy mixed workspaces cannot create new research runs."
}
```
5. If workspace is `fixed_symbol`:
   - expected symbol is `workspace.symbol`
   - if request `symbol` is present, normalize and compare
   - if mismatch, throw `BadRequestException` with:
```ts
{
  code: "symbol_workspace_mismatch",
  expected_symbol: workspace.symbol,
  received_symbol: normalizedRequestSymbol
}
```
   - create the run using `workspace.symbol`

Tests:
- fixed workspace + no symbol creates run with workspace symbol
- fixed workspace + matching symbol creates run
- fixed workspace + mismatched symbol returns `400 symbol_workspace_mismatch`
- legacy mixed workspace returns `400 legacy_workspace_read_only`
- existing header/body workspace mismatch behavior remains unchanged

## Rollout Notes

1. This is intentionally not a Continuity-only version. It should be implemented as a workspace feature because it affects research creation, history, thesis library, and continuity.
2. Old data remains visible through `Legacy Mixed Workspace`; no V1 migration is required.
3. Keep `symbol` in create-run requests until all clients are updated. The backend still owns validation.
4. Archive, rename, strategy labels, and enforced timeframe can be added later without changing the fixed-symbol invariant.
